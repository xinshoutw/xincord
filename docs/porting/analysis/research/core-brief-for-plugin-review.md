## v3 (main) plugin contract — the baseline
- Plugin entry `object Event : PluginEvent(listener: Boolean)` or `PluginEventConfigure<C>(listener, C.serializer())` (Core/src/main/kotlin/core/plugin/PluginEvent.kt). Event IS a JDA ListenerAdapter; if listener=true it is added to JDA and receives ALL events; it routes itself with `GlobalUtil.checkCommandString(event, "full name")` (returns TRUE on MISMATCH) / `checkComponentIdPrefix` / `checkModalIdPrefix`.
- `load()` exports `lang/` from the plugin jar to `plugins/<Name>/lang/...` (keeps existing files unless `-Flang`), `PluginEventConfigure` reads `plugins/<Name>/config.yaml` (exported from jar if missing) with KAML `Yaml()`.
- `load()` runs AFTER JDA is built and ready. `guildCommands()/globalCommands()` collected after load.
- Class loading: per-plugin child-first `PluginSandboxClassLoader` (Core/src/main/kotlin/core/plugin/ClassLoader.kt) that can also load classes/resources from its `depend_plugins` (so ChatLogger sees SQLiteAPI classes, Economy sees GoogleSheetAPI, MusicPlayer sees AudioAPI's bundled libs). Plugin resources win over Core resources.
- `StringLocalizer<CmdFileSerializer>` (core/localizations/StringLocalizer.kt) decodes `lang/<locale>/register.yaml` into the plugin's typed data class, then flattens by **Kotlin property names via reflection** (camelCase, e.g. YAML `basic-calculate:` with `@SerialName("basic-calculate") val basicCalculate` → key `basicCalculate.name`). Missing key → NPE (`!!`).
- `MessageCreator` v2 (core/builtin/messagecreator/v2) reads `lang/<locale>/message/*.yaml`, KAML strictMode=false. Schema: `content`, `embeds[]` {`title: {text,url}`, `description`, `thumbnail_url`, `image_url`, `color_code`, `timestamp`, `author{name,url,icon_url}`, `footer{text,icon_url}`, `fields[]{name,value,inline}`, `model_key`}, `components[]` as YAML-tagged rows `!ButtonsComponent {buttons:[{uid:{k:v}, style:Int, label, url, emoji:{formatted|model_key}, disabled}]}`, `!StringSelectMenu {uid, placeholder, min, max, options[]}`, `!EntitySelectMenu {uid, select_target_type, channel_types}`; optional `is_components_v2`/`components_v2`. `uid` map → custom_id via the plugin's `ComponentIdManager.build(uid)`. `model_key` entries are replaced at runtime from a `modelMapper: Map<String, Any>` passed by plugin code.
- `ModalCreator` reads `lang/<locale>/modal/*.yaml`: {`uid: {k:v}` (→ modal id via ComponentIdManager), `title`, `text_inputs[]{uid, label, value, placeholder, min_length, max_length, style, required}`}.
- `ComponentIdManager(prefix, idKeys: Map<String, FieldType>)` (core/util/ComponentIdManager.kt): custom_id = `{prefix}{a}:{v};{b}:{v}` where a,b,… are assigned by idKeys insertion order; INT_HEX/LONG_HEX hex-encoded; values pass through a Substitutor; parse requires exactly one ':' per segment.
- `Placeholder` (core/builtin/placeholder/Placeholder.kt): global `bot_id`,`bot_name`; per-user cached substitutors (`Placeholder.get(user|member|event)`, `Placeholder.update(user, ...)` persists custom keys per user!) with keys user_id, user_mention, user_name, user_avatar_url, member_display_name, member_avatar_url, **member_fixed_name** ("nick (name)" or name), command_name, full_command_name, language, command_string, channel_id, channel_name, channel_category_name, subcommand_name, component_id/label/style/url/emoji/emoji_name/min/max/placeholder; helper families putGuild/putUser/putMember/putEvent/putTextChannel (guild_name_upper, guild_owner_mention, user_global_name, member_nickname_or_name, event_timestamp_*, channel_mention, etc., with optional prefix and "-" none-value).
- Storage: `JsonFileManager<T>` (Moshi + KotlinJsonAdapterFactory, compact JSON, creates file on init) and `JsonGuildFileManager<T>` (dir of `<guildId>.json`, eagerly loads all files). Mongo: `CacheDbManager(dbName).getCollection(name, memoryCache)`; documents are `{_id: key, value: <bson>, timestamp: ms}`; Lists wrapped as `{items:[...], itemTypeName:"java.class"}`.
- Auto-defer (core/logger/InteractionLogger.kt): ONLY slash commands and message-context commands get `deferReply(true)`. Buttons/modals/selects are NOT auto-deferred.
- JDA build: `createDefault` + `setEnabledIntents(GUILD_MEMBERS, SCHEDULED_EVENTS, GUILD_EXPRESSIONS)` + plugin intents; member cache OWNER+VOICE+plugin policies; DAVE voice encryption via `JDaveSessionFactory`.

## v4 (B) Core facts — apply these to every plugin
Paths are on B under Core/src/main/kotlin/core/.
- `plugin/Plugin.kt`: `interface Plugin { var config: PluginConfig; fun Module.definitions(){}; fun PluginContext.onLoad(){}; fun PluginContext.onUnload(){}; fun PluginContext.onReload(){onUnload();onLoad()}; fun commands(): List<CommandHandler>; fun components(): List<ComponentHandler>; fun listeners(): List<Any> }`. `PluginContext(pluginName, pluginDirectory=plugins/<Name>, logger)` + `val fileGetter = FileGetter(pluginDirectory, PluginContext::class.java)`.
- `plugin/PluginRegistry.kt`: per plugin a plain parent-first `URLClassLoader(jar, coreLoader)` — NO access to depend_plugins' classes (cross-plugin API use → NoClassDefFoundError at runtime), and resources that also exist in Core (`config.yaml`, `info.yaml`, `logback.xml`) resolve to Core's copy. Order: topo sort on depend_plugins only (soft deps ignored; missing hard dep NOT detected). `onLoad()` is called inside `discoverAndLoad()` **before JDA is built and before `JDA` is registered in Koin** (BotApplication.kt). `commands()`/`components()` are read once right after onLoad; `listeners()` read after JDA build. `onReload` is NEVER called by Core (console `reload` = full stop()+start(): onUnload, new classloader/new object instance, onLoad).
- `command/CommandRegistry.kt`: handlers stored under `handler.data.name` (top-level command name) but dispatched by `event.fullCommandName` → **any command with subcommands/subcommand groups is never dispatched** ("No handler found" warning, deferred reply never completed). Commands are either guild (default) or global (`isGlobal`).
- `command/ComponentRegistry.kt` + CoreEventListener (BotApplication.kt): component/modal handlers matched by `customId.startsWith(prefix)`, first match in registration order; plugin `listeners()` ALSO receive the same interaction events (possible double handling).
- `logger/InteractionLogger.kt`: auto-defers slash (`deferReply(true)`) AND buttons, modals, string selects, entity selects (`deferEdit()`), unless `--no-auto-defer-interactions`. → any component handler that then calls `replyModal`, `reply`, `deferReply`, `editMessage` on the event (instead of `hook`) fails with "already acknowledged"; ephemeral replies to button clicks are no longer possible. Message-context commands are no longer auto-deferred nor dispatched by the registry.
- `config/ConfigLoader.kt`: `ConfigLoader.load<T>(file, default = "/config.yaml")` exports the default via `ConfigLoader::class.java.getResourceAsStream(...)` = **Core's classloader → Core's own config.yaml (bot_token template)**, not the plugin's; then decodes with KAML `Yaml.default` (**strictMode = true**: unknown keys or missing required fields throw). Fresh install → plugin's config.yaml becomes a copy of Core's config → load fails. Existing v3 `plugins/<Name>/config.yaml` files are read, but strict mode now rejects keys that the new ConfigSerializer dropped/renamed.
- `util/FileGetter.kt` (B): `export(resourcePath, destination = pluginDir)` locates the jar via `clazz.protectionDomain.codeSource` — with `PluginContext.fileGetter` that is the **Core jar**, so plugin `lang/` is never exported; and even with a plugin class, `export("lang/", pluginDir)` strips the `lang/` prefix (writes `plugins/<Name>/zh-TW/...` instead of `plugins/<Name>/lang/zh-TW/...`). Check how each plugin exports resources.
- `i18n/Localizer.kt`: reads only `lang/<locale>/register.yaml`, flattens **raw YAML keys** (e.g. `basic-calculate.name`, `sub_commands`...). Plugins that kept v3 camelCase key constants (e.g. `basicCalculate.name`) silently get EMPTY localization maps (`LocaleMap.resolve` returns "" — an empty string used as a command/option NAME or DESCRIPTION would throw in JDA). Other files under lang/<locale>/ (e.g. `placeholder.yaml`) are no longer read by Core.
- `i18n/MessageTemplate.kt`: reads `lang/<locale>/message/*.yml|yaml` with KAML **strict** into a NEW schema: `{model_key?, content?, embeds[]{title:String, description, color:"#hex", footer{text,icon_url}, author{name,url,icon_url}, thumbnail:String, image:String, fields[]}, components[]{buttons[]{label, style:"PRIMARY|..|LINK", id, url, emoji, disabled} | string_select{id, placeholder, min_values, max_values, options[]} | entity_select{id, placeholder, min_values, max_values, types[]}}}`. `model_key` parsed but ignored. Component ids = `"$componentIdPrefix:$id"` (or raw id). The unchanged v3 YAML (title:{text}, image_url, color_code, !ButtonsComponent, uid maps, style ints) will FAIL to parse → logged error, then `buildCreate/buildEdit` throws `IllegalArgumentException("Message not found")`. No modal template support exists at all in B Core.
- `util/ComponentId.kt`: same wire format as v3 ComponentIdManager (`{prefix}{a}:{v};...`, chars by key order), no Substitutor, value may contain ':'; check per plugin that prefix + key ORDER are unchanged (persistent buttons on old messages must still parse).
- `placeholder/Substitutor.kt` + `Placeholder.kt`: builder extensions `withUser/withMember/withGuild/withCommand/withBot` providing only: user_id,user_name,user_mention,user_avatar_url,user_is_bot,user_created_unix/iso; member_id,member_display_name,member_nickname(falls back to effectiveName),member_avatar_url,member_roles_count,member_roles_mentions(", "),member_roles_names,member_joined_unix/iso; guild_id,guild_name,guild_member_count,guild_icon_url(""),guild_owner_id; command_name,full_command_name,command_string,channel_id,channel_name,subcommand_name; bot_id,bot_name. NOT provided: member_fixed_name, language, channel_category_name, component_*, extended guild_/user_/event_ keys, prefixes. No per-user persistent substitutor (`Placeholder.update` semantics gone). Missing keys render literally as `%key%`.
- `util/JsonFile.kt`: `JsonFile<T>(file, KSerializer<T>, default)` (kotlinx Json: prettyPrint, ignoreUnknownKeys, encodeDefaults; parse failure → logs and returns default, next save() overwrites the bad file; does NOT create file on init; not synchronized) and `GuildJsonFile<T>(dir, serializer, defaultFactory)` (lazy per-guild `<guildId>.json`, cache not thread-safe, `remove()` deletes file). Compare JSON field names: Moshi used Kotlin property names unless `@Json(name=...)`; kotlinx uses property names unless `@SerialName`. Moshi tolerated missing fields with defaults similarly, but types like Long-as-String or Map<Long,...> keys may differ.
- `database/DatabaseProvider.kt` (Mongo coroutine driver; embedded or external), `Collection<T>` stores T itself as the document (NO `{_id,value,timestamp}` wrapper) → cannot read v3 documents; `GuildCollection` names collections `<prefix>_<guildId>`.
- `BotApplication.kt`: JDA via jda-ktx `light(token)` = `JDABuilder.createLight` → GatewayIntent.DEFAULT (non-privileged) + plugin `require_intents`. **GUILD_MEMBERS (privileged) is no longer enabled by Core** (v3 always enabled it) → GuildMemberJoin/Remove events not delivered unless a plugin's info.yaml requests it (none do). All CacheFlags off except plugin-requested; member cache NONE unless requested. No DAVE (`JDaveSessionFactory`) → voice connections may fail. `JDA` is put into Koin only after plugins are loaded.
- Koin: no plugin overrides `definitions()`. A few plugins call Koin (`get<JDA>()`, `get<DatabaseProvider>()`) — check timing (onLoad runs before JDA exists).
- Coroutines: slash/component handlers run on `Dispatchers.Default` in CoreEventListener's scope (multi-threaded; shared mutable maps in plugins may race).
